Problem

There is currently no good way to systematically describe, investigate or test file system behaviour, or compare behaviours across platforms and file systems.

Impact: developer uncertainty

➤ Common question How to interpret POSIX?
➤ Application developers How does a particular libc+OS+file system behave? What platform-specific behaviours should I worry about when porting apps?
➤ OS, libc and file system developers What do other OSes do here? Is my bugfix correct for all possible scenarios? Does my testing cover all cases?

Solution: SibylFS

✔ Model of POSIX and real-world file systems
✔ Real-world variants for Linux, Mac, FreeBSD
✔ Mathematically rigorous, precise, unambiguous, readable(ish), maintainable, comprehensive, detailed
✔ Models non-determinism, envelope of behaviours
✔ Usable as a test oracle

Model excerpt

SibylFS as test oracle

✔ Handles all traces, enables combinatorial testing
✔ Extensive test-suite (based on formal properties and derived equivalence classes)
✔ Comprehensible output (accept/reject with details)
# Error:   6: EPERM
#   unexpected results: EPERM
#   allowed are only: EEXIST, ENOTEMPTY
#   continuing with EEXIST, ENOTEMPTY
✔ HTML-based tools (multi-platform analysis at scale)
✔ Fast: >21k tests run and checked in <5mins

Test results

✔ >40 different combinations of libc/OS/file system, representing >800k test executions
✔ Accurate model: trace acceptance >99%
✔ Good coverage: >98% (of model)
✔ Platform variations analysed, documented
✔ Bugs found: in POSIX spec and file system/OS implementations (a few serious)

Pain points

➤ Interpreting POSIX and other documentation
➤ Analysing tens of thousands of traces manually
➤ Constructing model to match real-world behaviours
➤ Testing with equivalence classes: manually identifying non-satisfiable combinations of properties
